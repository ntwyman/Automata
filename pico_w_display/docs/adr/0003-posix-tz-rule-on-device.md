# POSIX TZ rule on device, `M`-form subset, UTC default

The Wall Clock converts Sync'd UTC to local time with a persisted POSIX TZ string (`TZ <posix>`), not a fixed UTC offset and not an IANA zone name. A fixed offset is wrong for half the year anywhere with DST, and IANA names would need the tz database (or a table derived from it) in flash; a POSIX rule is a few dozen bytes, encodes DST transitions directly, and its evaluation is pure, host-testable code. Only the `Mm.w.d[/time]` transition form is accepted (plus quoted `<…>` names, which many real zones' tz-database POSIX strings use); the `Jn` and `n` day-of-year forms are rejected with `ERR bad tz` since no inhabited zone needs them. Transition `/time`s may be negative or up to 167h (RFC 8536's extension, which tz-database strings for e.g. Nuuk and Israel use), and a rule naming a DST zone with no transitions (`EST5EDT`) takes the US rules, as glibc does. When no rule has ever been set the device shows UTC rather than a build-time guess — an obviously-wrong hour on a 24-hour display is the cue to send `TZ`. Mapping the phone's IANA zone to a POSIX string is the companion app's job, not the firmware's.
