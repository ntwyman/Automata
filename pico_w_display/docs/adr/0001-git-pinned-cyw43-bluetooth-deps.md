# Git-pinned `cyw43`/embassy deps for BLE, with WiFi+BLE concurrency risk accepted

Enabling Bluetooth on the CYW43439 requires `cyw43::new_with_bluetooth`, which isn't in a released `cyw43` version yet — only on a specific `embassy-rs/embassy` git commit, pulling `cyw43-pio`/`embassy-rp`/`embassy-sync`/`embassy-executor`/`embassy-time` along via `[patch.crates-io]` to keep the workspace on one consistent commit. We proceeded on this git-pinned combination (matching the official `embassy-rs/trouble` `rp-pico-2-w` example) rather than waiting for a crates.io release, and accepted the known open upstream bug embassy-rs/embassy#7081 (WiFi+BLE run concurrently can panic/deadlock on the Pico 2 W) as a monitored risk rather than a blocker — both radios running together is core to this feature (BLE control while Wi-Fi stays joined), so there's no way to sidestep the risk by design. Revisit the pin once `cyw43` cuts a release with Bluetooth support and #7081 is resolved upstream.

**Update (2026-10-09):** once BLE advertises only for onboarding and recovery (#18), both radios no longer run together all the time. That shrinks the #7081 exposure to onboarding and recovery, but doesn't remove it, so the pin and the risk both remain.
